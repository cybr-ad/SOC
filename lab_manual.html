৩. VMware Workstation-এ ভার্চুয়াল নেটওয়ার্ক তৈরি (১ মিনিটের কাজ)

💡 কেন VMware-এ Gateway IP সবসময় .2 (192.168.10.2) দিতে হয়? (খুব গুরুত্বপূর্ণ কনসেপ্ট)
সাধারণ বাসা-বাড়ির রাউটারে রাউটারের আইপি সাধারণত 192.168.1.1 থাকে। কিন্তু VMware Workstation NAT নেটওয়ার্কে আর্কিটেকচারটি ভিন্ন:
  • 192.168.10.1 (Host Virtual Adapter): এটি আপনার মূল পিসির নিজস্ব ভার্চুয়াল কার্ডের আইপি (VMware Network Adapter VMnet8)। আপনার মূল কম্পিউটার কোনো রাউটার নয়, তাই একে গেটওয়ে বানালে সে ইন্টারনেট ট্রাফিক পাস করতে পারে না।
  • 192.168.10.2 (VMware NAT Virtual Router): এটি VMware-এর নিজস্ব ভার্চুয়াল রাউটার সার্ভিস (vmnat.exe)। ইন্টারনেট অ্যাক্সেসের জন্য ভার্চুয়াল মেশিনগুলোকে অবশ্যই তাদের গেটওয়ে হিসেবে 192.168.10.2 কে পয়েন্ট করতে হয়।
  • 192.168.10.20: আমাদের Windows Server Domain Controller (DC01)।
  • 192.168.10.30: আমাদের Ubuntu Linux Server (srv-linux-01)।
সারসংক্ষেপ: হোস্ট পিসির Splunk-কে পয়েন্ট করতে আইপি হবে 192.168.10.1, কিন্তু ইন্টারনেটে যাওয়ার জন্য গেটওয়ে হবে 192.168.10.2।

উইন্ডোজ ও লিনাক্স সার্ভার যেন নিজেদের মধ্যে যোগাযোগ করতে পারে এবং ইন্টারনেট পায়:

  1. VMware Workstation ওপেন করে ওপরের মেনু বার থেকে ক্লিক করুন: Edit ➔ Virtual Network Editor।
  2. নিচে ডানপাশে একটি শিল্ড আইকনসহ Change Settings বাটনে ক্লিক করে পারমিশন (Yes) দিন।
  3. ওপরের তালিকা থেকে VMnet8 (যার পাশে NAT লেখা আছে) সেটিতে ক্লিক করুন।
  4. নিচে মানগুলো দিন:
    • Subnet IP: 192.168.10.0 | Subnet Mask: 255.255.255.0
  5. ডানপাশের NAT Settings বাটনে ক্লিক করুন ➔ নিশ্চিত করুন Gateway IP: দেওয়া আছে 192.168.10.2 (যদি .1 থাকে তবে পরিবর্তন করে .2 দিন) ➔ OK চাপুন।
  6. নিচে Apply এবং তারপর OK চেপে বের হয়ে আসুন।

ধাপ ১: VMware-এ Windows VM তৈরি করা

⚠️ অত্যন্ত জরুরি: "Windows cannot find Microsoft Software License Terms" এরর সমাধান
উইন্ডোজ সার্ভার ইন্সটল করার সময় যদি "Windows cannot find the Microsoft Software License Terms" এরর আসে, তবে এটি VMware-এর Easy Install (Virtual Floppy) কনফ্লিক্টের কারণে হয়।
দ্রুত সমাধান (২ মিনিটের ফিক্স):

  2. VM-এর ওপর রাইট ক্লিক করে Settings (অথবা Edit virtual machine settings) এ যান।
  3. Hardware লিস্ট থেকে Floppy (বা Floppy Drive) সিলেক্ট করে নিচে Remove বাটনে ক্লিক করে ডিলিট করে দিন।
  4. Memory ন্যূনতম 4096 MB (4 GB) আছে কিনা চেক করে OK চাপুন।
  5. এবার VM-টি চালু (Power On) করুন। কোনো এরর ছাড়াই স্মুথভাবে উইন্ডোজ সেটআপ শুরু হয়ে যাবে।

  1. VMware ওপেন করে ক্লিক করুন: Create a New Virtual Machine ➔ Typical (recommended) ➔ Next।
  2. Installer disc image file (iso) সিলেক্ট করুন ➔ Browse এ ক্লিক করে আপনার ডাউনলোড করা Windows Server ISO ফাইলটি দেখিয়ে দিন ➔ Next চাপুন।
  3. Easy Install স্ক্রিন আসলে:
    • Product Key: ফাঁকা রাখুন।
    • Version to install: Windows Server 2022 Standard
    • Full name: Administrator | Password: P@ssw0rd2026! | Confirm: P@ssw0rd2026!
    • Next চাপুন (পপআপ আসলে Yes দিন)।
  4. Virtual machine name: দিন DC01-CORP ➔ Next চাপুন।
  5. Disk Capacity: 60.0 GB দিন এবং নিচে Store virtual disk as a single file সিলেক্ট করে Next দিন।
  6. Customize Hardware বাটনে ক্লিক করে:
    • Memory: দিন 4096 MB (কম্পিউটারে র‍্যাম কম থাকলে 2048 MB দিন)।

ধাপ ২: উইন্ডোজ সার্ভারে স্ট্যাটিক আইপি কনফিগার করা

  1. উইন্ডোজ ইনস্টল শেষ হলে VMware মেনু থেকে VM ➔ Send Ctrl+Alt+Delete দিয়ে লগইন করুন (পাসওয়ার্ড: P@ssw0rd2026!)।
  2. উইন্ডোজের ভেতরে Start আইকনে রাইট ক্লিক করে Windows PowerShell (Admin) ওপেন করুন।
  3. নিচের কমান্ড দুটি হুবহু পেস্ট করে Enter চাপুন: 
    # বিদ্যমান আইপি রিমুভ করে নতুন স্ট্যাটিক আইপি সেট করা (MSFT_NetIPAddress already exists এরর এড়াতে):
Remove-NetIPAddress -InterfaceAlias "Ethernet0" -AddressFamily IPv4 -Confirm:$false -ErrorAction SilentlyContinue

New-NetIPAddress -InterfaceAlias "Ethernet0" -IPAddress 192.168.10.20 -PrefixLength 24 -DefaultGateway 192.168.10.2
Set-DnsClientServerAddress -InterfaceAlias "Ethernet0" -ServerAddresses ("127.0.0.1", "1.1.1.1")

৫. অ্যাক্টিভ ডিরেক্টরি ফরেস্ট (Active Directory Forest) তৈরি ও ডোমেইন অবজেক্ট

💡 ফরেস্ট (Forest) কী এবং কীভাবে তৈরি হয়?
অ্যাক্টিভ ডিরেক্টরিতে Forest হলো সিকিউরিটির সর্বোচ্চ সীমানা (Ultimate Security Boundary)। যখন কোনো সার্ভারকে প্রথম ডোমেইন কন্ট্রোলার হিসেবে প্রোমোট করা হয় (যেমন: corp.local), তখন সেটি মূলত একটি নতুন **Active Directory Forest** এর ভিত্তি (Forest Root) তৈরি করে। এই ফরেস্টের ভেতরে একাধিক Organizational Unit (OU), ইউজার, গ্রুপ এবং পলিসি তৈরি করে পুরো করপোরেট নেটওয়ার্ককে সাজানো হয়।

ধাপ ১: ফরেস্ট প্রমোশন স্ক্রিপ্ট চালানো

⚠️ অতীব গুরুত্বপূর্ণ: স্ক্রিপ্টটি কোথায় ও কীভাবে রান করবেন? (Host vs VM)
setup_ad_dc.ps1 স্ক্রিপ্টটি আপনার মূল কম্পিউটারে (হোস্টে) রান করবেন না! এটি উইন্ডোজ সার্ভারের জন্য তৈরি।
সঠিক নিয়ম (৩টি সহজ ধাপ):
  1. মূল কম্পিউটার থেকে scripts ফোল্ডারটি কপি করুন।
  2. VMware-এর ভেতরে Windows Server VM (DC01-CORP) এর ডেস্কটপে পেস্ট করুন (পাথ হবে: C:\Users\Administrator\Desktop\scripts)।
  3. উইন্ডোজ সার্ভার VM-এর ভেতরের Windows PowerShell (Admin) ওপেন করে রান করুন।
টেকনিক্যাল নোট: স্ক্রিপ্টটিতে মাইক্রোসফট স্ট্যান্ডার্ড Parameter Splatting এবং UTF-8 with BOM ব্যবহার করা হয়েছে, যার ফলে কোনো প্রকার কোটেশন বা সিনট্যাক্স এরর ছাড়াই এটি নির্বিঘ্নে চলবে।

Windows Server VM-এর ভেতরের PowerShell (Admin) ওপেন করে কমান্ডটি চালান:

cd C:\Users\Administrator\Desktop\scripts
.\setup_ad_dc.ps1 -DomainName "corp.local" -NetbiosName "CORP"
⚠️ সার্ভার স্বয়ংক্রিয়ভাবে রিবুট হবে
এটি নিজে নিজে corp.local ফরেস্ট তৈরি করবে, Event 4688 এ Command-Line লগিং এবং PowerShell Script Block logging চালু করবে এবং সার্ভার রিস্টার্ট নিবে। রিস্টার্টের পর CORP\Administrator হিসেবে লগইন করুন।

ধাপ ২: ফরেস্টের ভেতরে বিভাগভিত্তিক OU, গ্রুপ ও ইউজার তৈরি করা

ল্যাবে বাস্তবসম্মত করপোরেট পরিবেশ তৈরির জন্য রিস্টার্টের পর PowerShell (Admin) এ নিচের কমান্ডগুলো রান করুন:

# ১. বিভাগভিত্তিক Organizational Units (OUs) তৈরি:

# ১. প্রয়োজনীয় টুলস ইনস্টল:

wget -O splunkforwarder.deb "https://download.splunk.com/products/universalforwarder/releases/9.1.2/linux/splunkforwarder-9.1.2-b6b9c8185839-linux-2.6-amd64.deb"
sudo dpkg -i splunkforwarder.deb

# ৩. inputs.conf ও outputs.conf স্বয়ংক্রিয় কনফিগার:
sudo mkdir -p /opt/splunkforwarder/etc/system/local

sudo tee /opt/splunkforwarder/etc/system/local/inputs.conf > /dev/null << 'EOF'
[default]
host = srv-linux-01

[monitor:///var/log/auth.log]
disabled = false
sourcetype = linux_secure
index = linux_logs

[monitor:///var/log/audit/audit.log]
disabled = false
sourcetype = linux_audit
index = linux_logs
EOF

sudo tee /opt/splunkforwarder/etc/system/local/outputs.conf > /dev/null << 'EOF'
[tcpout]
defaultGroup = default-autolb-group

[tcpout:default-autolb-group]
server = 192.168.10.1:9997

[tcpout-server://192.168.10.1:9997]
EOF

sudo /opt/splunkforwarder/bin/splunk start --accept-license --answer-yes
sudo /opt/splunkforwarder/bin/splunk enable boot-start -user splunk

৯. হোস্ট থেকে ১-ক্লিকে ইউনিভার্সাল অটো-ডিপ্লয়ার (setup_universal.bat) ও ভিএম লাইফসাইকেল

💡 স্টুডেন্টদের জন্য ১-ক্লিক ইউনিভার্সাল লঞ্চার কী এবং কীভাবে কাজ করে?
শিক্ষার্থীরা তাদের কম্পিউটারের যেকোনো ড্রাইভে (যেমন: C:, D:, বা E:) ল্যাব ফোল্ডার রাখুক না কেন, setup_universal.bat ফাইলটিতে ডাবল-ক্লিক করলেই এটি কোনো ড্রাইভ বা পাথের ওপর নির্ভর না করে স্বয়ংক্রিয়ভাবে পুরো ল্যাব প্রস্তুত করে দেয়।

১. setup_universal.bat রান করলে ধাপে ধাপে কী কী কাজ সম্পন্ন হয়?

  1. স্বয়ংক্রিয় অ্যাডমিনিস্ট্রেটর এলিভেশন (UAC Auto-Elevation): ফাইলটিতে ডাবল-ক্লিক করামাত্র এটি উইন্ডোজ থেকে স্বয়ংক্রিয়ভাবে Administrator প্রিভিলেজ চেয়ে নেয়, ফলে কোনো ফোল্ডার পারমিশন এরর আসে না।
  2. ডায়নামিক পাথ ও ভিএম ডিসকভারি: এটি নিজে যেখানে আছে সেখান থেকে প্রোজেক্ট রুট চিনে নেয় এবং VMware-এর রানিং ভিএম লিস্ট থেকে DC01-CORP ও srv-linux-01 কে অটো-ডিটেক্ট করে।
  3. হোস্ট স্প্লাঙ্ক ও ফায়ারওয়াল প্রস্তুত করা (Phase 1):
    • উইন্ডোজ ফায়ারওয়ালে ইনবাউন্ড পোর্ট TCP 9997 খুলে দেয়।
    • হোস্টের Splunk-এ [splunktcp://9997] রিসিভার কনফিগার করে।
    • কাস্টম ইনডেক্স (win_logs, sysmon, linux_logs) যুক্ত করে Splunkd সার্ভিস রিস্টার্ট দিয়ে সক্রিয় করে।
  4. উইন্ডোজ সার্ভারে টেলিমেট্রি ডিপ্লয়মেন্ট (Phase 2):
    • VMware গেস্ট টুলের মাধ্যমে DC01-CORP এর ভেতরে Sysmon64 এবং Splunk Universal Forwarder স্বয়ংক্রিয়ভাবে পুশ ও ইনস্টল করে।
    • উইন্ডোজ সিকিউরিটি লগ, সিসমন ইভেন্ট এবং পাওয়ারশেল স্ক্রিপ্ট ব্লক লগ হোস্টের স্প্লাঙ্কে পাঠানোর জন্য কনফিগার করে দেয়।
  5. উবুন্টু লিনাক্স সার্ভারে অডিট ও ফরওয়ার্ডার ডিপ্লয়মেন্ট (Phase 3):
    • উবুন্টুর লাইভ আইপি ডায়নামিক্যালি স্ক্যান করে খুঁজে বের করে (স্ট্যাটিক বা ডিএইচসিপি যেকোনো আইপিতেই কাজ করে)।
    • লিনাক্সে auditd ইনস্টল ও কনফিগার করে এবং Splunk Universal Forwarder ইনস্টল করে হোস্টের স্প্লাঙ্কে লগ পাঠানো শুরু করে দেয়।

⚠️ সমস্যার মূল কারণ: Internet Explorer Enhanced Security Configuration (IE ESC)
উইন্ডোজ সার্ভার ওএসে ডিফল্ট সিকিউরিটি হিসেবে IE ESC চালু থাকে। যখন PowerShell 5.1-এ Invoke-WebRequest -Uri "http://www.google.com" চালানো হয়, তখন পাওয়ারশেল ব্যাকগ্রাউন্ডে ওয়েবসাইটের এইচটিএমএল ও স্ক্রিপ্ট পার্স করার জন্য পুরোনো Internet Explorer ইঞ্জিন (MSHTML) ব্যবহার করার চেষ্টা করে। গুগলের স্ক্রিপ্টগুলো IE ESC দ্বারা ব্লকড হওয়ায় এই সতর্কতা উইন্ডোটি সামনে চলে আসে।

স্থায়ী সমাধান:

  • পদ্ধতি ১ (সর্বোত্তম সমাধান): PowerShell-এ কমান্ড দেওয়ার সময় সবসময় -UseBasicParsing প্যারামিটার যোগ করুন: 
    Invoke-WebRequest -Uri "http://www.google.com" -UseBasicParsing
    এটি ইন্টারনেট এক্সপ্লোরার ইঞ্জিন বাইপাস করে সরাসরি লাইটওয়েট HTTP GET রিকোয়েস্ট পাঠায় এবং কোনো পপ-আপ ছাড়া তৎক্ষণাৎ StatusCode: 200 OK রিটার্ন করে।
  • পদ্ধতি ২ (সার্ভারে IE ESC বন্ধ করা): Server Manager ➔ Local Server ➔ IE Enhanced Security Configuration এ গিয়ে Administrators-এর জন্য "Off" করে দিন।

শিক্ষার্থীরা যখন ক্লাসে জিজ্ঞাসা করবে: "স্যার, উইন্ডোজের নিচে ইন্টারনেট আইকনে কেন পৃথিবীর গোল চিহ্ন দেখাচ্ছে, ইন্টারনেট কি কাজ করছে না?"—তখন তাদের নিচের পয়েন্টগুলো বুঝিয়ে বলুন:
  1. "ইন্টারনেট কিন্তু সার্ভারে সম্পূর্ণ সচল আছে!" — দেখ প্রমাণ: PowerShell-এ Test-NetConnection 8.8.8.8 চালালে TcpTestSucceeded : True আসছে এবং Resolve-DnsName google.com দিলে গুগলের লাইভ আইপি 142.250.29.113 নিখুঁতভাবে আসছে। এজ ব্রাউজারে গুগল ওপেন করলেও পেজ লোড হচ্ছে।
  2. তাহলে গ্লোব আইকন কেন দেখাচ্ছে? — উইন্ডোজের টাস্কবারের আইকন নিয়ন্ত্রণ করে উইন্ডোজের একটি বিশেষ সার্ভিস যার নাম NCSI (Network Connectivity Status Indicator)। এটি মাইক্রোসফটের সার্ভারে (msftconnecttest.com) একটি প্রাথমিক প্রোব পাঠায়।
  3. ডোমেন কন্ট্রোলারের বুট টাইমিং: আমাদের সার্ভারটি একটি Active Directory Domain Controller (DC)। এর প্রাইমারি DNS হলো 127.0.0.1 (সার্ভার নিজে)। সিস্টেম যখন অপ্রত্যাশিত রিস্টার্ট বা পাওয়ার অন হয় ("Shutdown Event Tracker" পপ-আপের মতো অবস্থায়), তখন উইন্ডোজ ওএস লোড হওয়ামাত্রই NCSI প্রোব চেক করতে যায়। কিন্তু তখনও ডোমেন কন্ট্রোলারের নিজস্ব DNS সার্ভিস ও NAT ফরওয়ার্ডার পুরোপুরি সক্রিয় হতে কয়েক সেকেন্ড সময় লাগায় প্রথম চেকিংয়ে NCSI রেসপন্স না পেয়ে সতর্কতামূলকভাবে এই গ্লোব আইকন ঝুলিয়ে দেয়।
  4. সারসংক্ষেপ: এটি কোনো নেটওয়ার্ক ফেইলিওর নয়, এটি উইন্ডোজের একটি নিরীহ কসমেটিক স্ট্যাটাস ইন্ডিকেটর। সার্ভারের যাবতীয় ব্যাকগ্রাউন্ড ট্রাফিক, ব্রাউজিং, প্যাকেজ ডাউনলোড এবং স্প্লাঙ্কে লগ পাঠানো শতভাগ স্বাভাবিকভাবে কাজ করছে।

১. ফরওয়ার্ডার দিয়ে কীভাবে এই লগগুলো স্প্লাঙ্কে পাঠাবেন? (Step-by-Step)

ক) উইন্ডোজ সার্ভার (DC01-CORP) থেকে লগ পাঠানো:

  1. ফাইলটি উইন্ডোজ সার্ভারের C:\Logs\windows_attacks_sample.log ডিরেক্টরিতে রাখুন।
  2. উইন্ডোজ সার্ভারে Administrator PowerShell ওপেন করে ফরওয়ার্ডারে মনিটর কমান্ড দিন: 
    & "C:\Program Files\SplunkUniversalForwarder\bin\splunk.exe" add monitor "C:\Logs\windows_attacks_sample.log" -index win_logs -sourcetype custom_windows_attacks -auth admin:P@ssw0rd2026!
  3. ফরওয়ার্ডার সার্ভিসটি রিস্টার্ট দিন: 
    Restart-Service SplunkForwarder

খ) উবুন্টু লিনাক্স সার্ভার (srv-linux-01) থেকে লগ পাঠানো:

  1. ফাইলটি উবুন্টু সার্ভারের /var/log/linux_attacks_sample.log ডিরেক্টরিতে রাখুন।
  2. উবুন্টু টার্মিনালে লগ মনিটর কমান্ড রান করুন: 
    sudo /opt/splunkforwarder/bin/splunk add monitor /var/log/linux_attacks_sample.log -index linux_logs -sourcetype custom_linux_attacks -auth admin:changeme
  3. অথবা inputs.conf ফাইলে যুক্ত করে ফরওয়ার্ডার রিস্টার্ট দিন: 
    sudo /opt/splunkforwarder/bin/splunk restart

২. ফরওয়ার্ডার ইন্সটল ও লগ মনিটর হচ্ছে কি না কীভাবে চেক করবেন?

Windows DC01 ভেরিফিকেশন
Get-Service SplunkForwarder
& "C:\Program Files\SplunkUniversalForwarder\bin\splunk.exe" list monitor
Linux Server ভেরিফিকেশন
sudo /opt/splunkforwarder/bin/splunk status
sudo /opt/splunkforwarder/bin/splunk list monitor
